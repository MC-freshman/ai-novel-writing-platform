# 本地向量配置指南（P89）

本平台的向量检索默认使用**本地哈希向量**（离线、零配置、语义较弱）。配置 embedding 接口后可获得语义检索；**完全离线方案**是用本机 Ollama 提供 embedding 服务。

## 1. 能力现状

- 向量接口走 OpenAI 兼容 `/embeddings` 协议；**本地地址（127.0.0.1/localhost）无需 API 密钥**（代码已支持）。
- 检索已是**关键词 + 向量混合评分**（lexicalRelevanceScore + compatibleVectorScore），无需额外开关。
- 向量接口失败时自动降级本地哈希向量，界面给出提示；可在知识库维护工具重建索引。
- 磁盘分片格式 v3；维度变化（换模型）后需重建索引。

## 2. Ollama 本地语义向量（推荐离线方案）

1. 安装 Ollama（https://ollama.com），拉取一个 embedding 模型，例如：
   - `ollama pull nomic-embed-text`（768 维，英文为主，中文可用）
   - `ollama pull bge-m3`（1024 维，多语言，中文效果更好，体积更大）
2. 确认服务运行：`ollama serve`（默认 http://127.0.0.1:11434）。
3. 平台设置 → 向量检索：
   - 点「Ollama 本地预设」自动填入地址 `http://127.0.0.1:11434/v1` 与模型 `nomic-embed-text`（可改为 bge-m3）。
   - 点「测试向量连接」：返回维度/耗时即成功；失败会显示原因（服务未启动/模型未拉取/地址错误）。
4. 保存设置后，在知识库执行「重建索引」，让全部资料用新模型重新向量化。

## 3. 云端 embedding

设置 → 向量检索：填写接口地址（如 `https://dashscope.aliyuncs.com/compatible-mode/v1`）、模型（如 `text-embedding-v3`）、密钥。密钥保存在 Windows 凭据管理器。

## 4. 容量与性能参考（本机实测，合成数据）

| 片段数 | 维度 | 热检索 P95 | 峰值内存 |
|---|---|---|---|
| 3 万 | 384 | ~40ms | ~330MB |
| 10 万 | 384 | ~102ms | ~710MB |
| 20 万 | 384 | ~294ms | ~1.0GB |
| 20 万 | 1024 | ~590ms | ~1.7GB |

大维度模型（1024+）首次装载较慢（20 万片段约 28 秒），请预留内存。详见 docs/检索容量实测_2026-10-11.md。

## 5. 故障排查

| 现象 | 处理 |
|---|---|
| 测试连接失败「fetch failed」 | Ollama 未启动或地址/端口错误；`ollama serve` 后重试 |
| 测试成功但检索仍降级 | 保存设置后重建索引；查看知识库诊断的向量降级提示 |
| 换模型后检索异常 | 维度变化必须重建索引（旧向量与新查询维度不一致） |
| 中文语义效果差 | 换多语言模型（bge-m3）；小模型中文能力有限 |
