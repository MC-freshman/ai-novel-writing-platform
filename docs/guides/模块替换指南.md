# 模块替换指南（P73 通用模块框架）

平台的可替换功能以「模块槽」组织：每个槽位有契约（contract）、内置实现（builtin）与注册表（registry）。宿主只经注册表挂载模块，不静态依赖内置实现；停用或替换模块不删除数据。

## 1. 现有槽位

| 槽位 | 契约 | 内置实现 | 能力 |
|---|---|---|---|
| mindmap | src/modules/mindmap/contract.ts（v1） | src/modules/mindmap/builtin.tsx → components/planning/MindMaps | tree-edit / relations / notes / layout / xmind-import / fullscreen |

后续槽位（导出提供者、TTS 引擎、图像提供者、备份目标、词库提供者、文件桥、导入提供者等）随对应 P 表条目落地，统一复用 `src/modules/core/registry.ts` 的 `createModuleRegistry` 与 `declareModuleSlot`。

外部软件接入（不作为渲染层模块）：见「外部MCP接入指南.md」（MCP 服务）与后续文件桥条目。

## 2. 启用 / 禁用

- 设置 → 模块管理：按槽位开关。配置存于 `novel.config.json` 的 `modules.<槽位>.enabled`；mindmap 槽同时兼容旧 `ui.mindMapEnabled` 字段。
- 禁用 = 隐藏入口 + 显示停用提示 + **数据保留**；重新启用即恢复。
- 卸载守卫：有未落盘草稿时阻止注销（保存失败不允许禁用/替换）。

## 3. 替换为自研实现（三条路径）

### 路径 A：构建期源码替换（推荐，随包分发）

许可允许个人私下修改。以 mindmap 为例：

0. **完整性校验（P102）**：替换前对你的模块包生成/校验 SHA256 清单，防止被篡改的模块进入构建：
   ```powershell
   npm run verify:module -- src/modules/mindmap-my --generate   # 首次生成清单
   npm run verify:module -- src/modules/mindmap-my              # 之后校验（篡改/缺失/未登记均报错）
   ```
   注意：运行时加载外部 JS 仍被 CSP `script-src 'self'` 禁止（安全纪律，不放宽）；本工具只服务构建期替换。
1. 新建 `src/modules/mindmap-my/`，实现 `MindMapModule`（descriptor.contractVersion 必须等于 `MIND_MAP_CONTRACT_VERSION`，capabilities 必须覆盖全部必需能力，组件 Props 见 contract.ts）。
2. 修改 `src/main.tsx` 的注册语句，把 `builtinMindMapModule` 换成你的模块（保持经注册表注册）。
3. `npm run build && npm run start` 验证；`npm run test:ui-planning-boards` 检查行为契约。
4. 恢复内置：还原 main.tsx 注册语句即可；数据格式不变。

约束：`check:modules` 门禁禁止宿主组件静态导入任何 `modules/*/builtin`；你的实现同样只能经注册表挂载。

### 路径 B：运行时注册表 API（开发/调试）

渲染进程全局 `window.novelModules` 暴露：

```js
window.novelModules.registerMindMapModule(myModule);      // 替换
await window.novelModules.unregisterMindMapModule();      // 注销（卸载守卫可能拒绝）
window.novelModules.registerBuiltinMindMapModule?.();     // 恢复内置（若启动时注册过）
```

可在 DevTools 控制台或你自己的注入脚本中调用。注意：CSP `script-src 'self'` 禁止运行时加载外部脚本包；打包版没有 DevTools 入口时此路径仅适用于源码运行。

### 路径 C：外部软件接入（进程外）

- **MCP**：自研/外部 MCP 服务经「设置 → 外部接入（MCP）」接入，平台生成客户端配置并只读自检；见外部MCP接入指南。
- **文件桥**（P74，规划中）：导出项目文件副本 → 外部程序编辑 → 侦测变化 → 预览确认回导。
- 进程内嵌入外部程序窗口不可行（沙箱 + CSP + Electron 无嵌入 HWND 官方 API），不要尝试。

## 4. 新增一个模块槽（开发者）

1. `src/modules/<slot>/contract.ts`：版本号、能力枚举、descriptor/Props 类型、`describe…Problem` 拒绝原因函数。
2. `src/modules/<slot>/registry.ts`：`createModuleRegistry<Module>()` + `declareModuleSlot({id,label,description,toggleLabel?})`；如需全局 API 再挂 window。
3. `src/modules/<slot>/builtin.tsx`：内置实现。
4. `src/main.tsx`：经注册表注册，附 `VITE_DISABLE_<SLOT>_MODULE` 构建开关。
5. 宿主组件：`useModule()` + 契约校验 + 降级提示 + 卸载守卫绑定保存。
6. 设置「模块管理」自动列出新槽位（数据驱动）；`config.modules.<slot>.enabled` 生效。
7. 测试：服务/契约测试入 `scripts/test/services/`；「未注册构建」降级验收参照 `scripts/test-ui-no-mindmap.cjs`。

## 5. 兼容承诺

- mindmap 契约 v1 与 `window.novelModules` API 保持不变；旧项目直接打开。
- 模块数据始终留在项目目录（如 `analysis/creative-workspace/state.json`），替换实现不得删除或迁移数据。
- 门禁：`npm run check:modules`（边界）、`npm run test:services`（含 module-registry 契约）、`npm run test:regression`（含未注册降级）。
## 6. 外部写入与 MCP（P101 裁定）

外部 AI 客户端对项目的**写入**由自研 `ai-novel-platform-mcp`（v3.1.0+）承担：10 个写入工具（章节写入/备份/重建索引/导图增删改/XMind 导入等）全部要求 `novel_plan` → `planId + confirmToken` 两步确认（令牌一次性、5 分钟过期、参数漂移失效），破坏性函数另需 `ack=DELETE`，写入走平台 `creative-workspace.cjs` 事务。

平台侧「外部接入（MCP）」面板的连接自检**保持只读**（设计纪律）：不在平台内新增第二条写路径，避免与自研 MCP 的确认机制重复或绕过。外部写入后在规划页点「刷新规划数据」，并遵守单写者原则。
