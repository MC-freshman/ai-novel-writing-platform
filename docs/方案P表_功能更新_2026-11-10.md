### 1.2 目标用户

- **primary：中文网文/长篇小说作者**——需要长期维护大量章节、大纲、人物关系与世界设定，日更压力大，重视不丢稿与隐私（README.md:23）。
- **secondary：注重数据主权的结构化写作者**——愿意自带 API Key（BYOK），接受本地 Ollama 或云端模型，不希望稿件被平台拿去训练（对应 2026 行业「本地优先 + 结构化 + AI 辅助」细分趋势，见 §2）。
- 用户技术水平分层：普通作者双击即用（便携版自带运行时，无需 Node）；进阶用户自行配置提供商/模型/检索上限。

## 3. 优先级筛选方法

评分 1–5：**V 用户价值**、**N 必要性**（不做是否持续失血）、**C 实现成本**（1 最低）、**R 风险**（1 最低）。
优先级规则：P1 = V+N≥8 且 C≤3 且 R≤3（或架构前置）；P2 = V+N≥6 且 C≤4 且 R≤3；P3 = 其余可执行项；不可行/越界项进 §7 不做清单。

## 5. 条目明细（实施步骤 / UI / 模块化 / 风险）

> 通用约定（适用于全部条目，验收时逐条核对）：
> **UI 基线**：复用 tokens.css 主题令牌、modal-surface 弹窗外壳、InlineFeedback 反馈、共享焦点围栏与应用内输入弹窗（禁 window.prompt）；按钮必须有名称/动作（run-ui-button-audit 通过）；无数据/无权限/模块停用时禁用或隐藏入口并给出状态文案；窄窗、150% DPI、暗色、长标题通过布局测量；新功能入口归入既有信息架构（设置分组/分析页签/右键菜单/Ctrl+K 面板），不新增顶层导航。
> **模块化基线（两级分层，审计 A23）**：
> **Tier A 可替换实现槽**（contract 版本+能力清单+descriptor+注册表挂载+卸载守卫+未注册降级测试）：mindmap（既有）、export-provider（P79）、import-provider（P91）、tts-engine（P84）、image-provider（P88）、backup-target（P80）、dictionary-provider（P77）、file-bridge（P74）、mcp-service（P81）。替换路径=构建期源码替换（许可允许个人修改）+运行时 window.novelModules 注册 API+外部软件经文件桥/MCP。
> **Tier B 功能模块**（独立服务+独立组件+`config.modules.<id>.enabled` 开关+禁用保留数据+源码级可替换）：P75/P76/P78/P82/P83/P85/P86/P87/P89/P90。不强制运行时注册表，避免过度设计。
> 通用规则：`config.modules.<id>.enabled` 控制启用/禁用；禁用=隐藏 UI+保留数据+状态提示（沿用 mindmap 模式，ProgressWorkspace.tsx:108-141）；Tier A 卸载守卫保护未落盘数据；每 Tier A 模块提供「未注册构建」降级验收（沿用 test-ui-no-mindmap 模式）；新服务必须登记测试证据（check:services）。
> **数据基线**：项目格式只增量添加字段/文件；写操作走 withProjectTransaction；二进制走主进程磁盘（C3）；密钥走 Windows 凭据管理器；导出/备份排除密钥（沿用交换包规则）。
